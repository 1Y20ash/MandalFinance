# MandalFinance Data Retention Schedule

Version: 1.0 | Owner: Mandal administration/privacy owner

Retention is purpose-driven. Where a financial, tax, statutory, dispute or security requirement requires longer retention, the applicable record is retained only for that requirement and access remains restricted.

| Category | Retention rule | Disposal method |
|---|---|---|
| Active account data | Account lifetime | Approved account closure: delete unnecessary data; anonymise fields that must remain linked to financial records |
| Consent records | While relevant to demonstrating the consent decision and for the applicable accountability period | Controlled deletion/anonymisation after expiry |
| Payment/financial records | As required by applicable accounting, tax, payment and dispute obligations | Preserve required records; remove unnecessary personal linkage where feasible |
| Financial audit records | Required audit/accountability period | Controlled archival/deletion; never silently rewrite history |
| Uploaded evidence documents | Only while required for the supported financial/audit purpose | Delete from private storage and remove metadata after approved retention expiry |
| Security/audit logs | Only as long as reasonably necessary for security, accountability and incident investigation | Redaction, anonymisation or deletion after schedule expiry |
| Sessions | Session lifetime | Automatic expiry/invalidation |
| Privacy requests | Through completion plus the documented accountability period | Restricted archival then controlled deletion/anonymisation |

## Review

The schedule must be reviewed at least annually and whenever a new data category, processing purpose, financial obligation or third-party processor is introduced.

## Deletion principle

Deletion is not a blind database cascade. The privacy owner must determine which personal data can be removed, which financial records must remain, and whether anonymisation can preserve accounting integrity without retaining unnecessary personal data.
